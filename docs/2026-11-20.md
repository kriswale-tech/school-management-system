# 20 November 2026

Schools that already have pupils can bring their records in. Marks are still outside the app. Fee reminders now follow the debt a parent can actually see.

## Bring the past

**Data migration** is in the school app for admins and staff. Accountants and teachers do not see it. Platform admin does not run it. One school can save one import at a time.

Four imports, from the migration home:

1. **Student information.** Current pupils. A student ID used twice in the file is held back on every one of those rows until the IDs are unique.
2. **Enrollment history.** One row per past term. Repeated student IDs are expected. The current term must match a real class. Older terms can stay as an old class, kept out of class setup, promotion, and fee class lists. A past year that is not on the calendar is created inactive, with three terms, and does not become the current year.
3. **Opening balances.** The amount still owed for one student and one term, when the old bills and receipts are not available. It becomes a bill named Opening balance. It is not a fee in Fees settings, and it is never overwritten by a later import.
4. **Fee history.** Two files on one import: charges, and payments. A charge is the net amount for one fee, one student, one year, and one term. A payment is that term’s share of the money. The same payment reference can cover more than one term and is stored as one payment. An advance is kept aside and is not spent when fees are applied or a student enrolls. The import does not print a SCHOOLASST receipt, send a text, or post an activity. The old receipt number still shows on payment history.

A term that already has an opening balance is left out of fee history. Other terms for that student still save. Empty fields on an existing student can be filled. A value that differs from what is already stored is kept unless someone resolves it. Fee history and opening balances never create a student.

Excel and CSV. Columns can be suggested and corrected. Extra columns are ignored. The file is private to the school. After an import is fully saved, the spreadsheet is removed and the screen is a report. A partly saved import keeps the file. Results list who was saved and who was not. While a save is still running, the not-saved list stays hidden. Opening a finished report no longer repeats the saved rows in the not-saved list.

Full rules: [migration.md](./migration.md).

## Fees and reminders

The fee list opens on the **current term**. **All time** is still in the filter. On All time, red means the lifetime bill is higher than the lifetime payments, including opening balances and fee history, for students enrolled this term.

**Remind parents** follows that filter. All time covers every term still owed. One chosen term covers only that term.

The automatic reminder, from Settings → Parent messages, now sends for **all debt** still owed by students enrolled this term. It names the terms in the total. It still runs only on the school’s schedule, and only when the total is at least the school’s minimum. Clearing this term does not stop a reminder if an older year is still unpaid.

## Amazon SES

Platform admin **Provider credits & accounts** is two tabs: **Arkesel** and **Amazon SES**.

With email on and AWS credentials set, **Sync usage** stores a live snapshot. Daily used and the daily cap are the SES rolling 24-hour send quota. Monthly sent is the CloudWatch `Send` total for the current month. SES has no monthly cap, so that limit stays empty. Received stays 0 while the identity only sends. Without credentials, sync still stores a placeholder and marks the account not configured.

Staff mail, login codes, and guardian batches use `SES_CONFIGURATION_SET` when it is set (`sms-email-events` in the example env). That configuration set is what publishes send, delivery, bounce, and complaint events.

The SES webhook confirms an SNS subscription by calling `SubscribeURL`. It only follows an `https` URL on `sns.<region>.amazonaws.com`. When `SES_SNS_TOPIC_ARN` is set, a confirmation for any other topic is ignored.

Super Admin and Operations can send one plain test email from the SES tab. It uses the same send path as the app. In the SES sandbox that message is delivered only to a verified address.

Checked the same day: `communications.tests.test_ses_usage` passed (5 tests: quota and monthly send, live snapshot, test-send payload, SNS host and topic checks), and the platform admin typecheck passed.
